OpenShapeForge API {{ .Chart.AppVersion }} deployed as {{ include "openshapeforge-api.fullname" . }}.

{{- if .Values.migration.enabled }}

Schema migrations ran as a pre-upgrade Job
({{ include "openshapeforge-api.fullname" . }}-migrate) using the privileged
database URL. Check it if the API pods are not ready:

  kubectl logs -n {{ .Release.Namespace }} job/{{ include "openshapeforge-api.fullname" . }}-migrate
{{- end }}

Reach the API inside the cluster at:

  http://{{ include "openshapeforge-api.fullname" . }}.{{ .Release.Namespace }}.svc:{{ .Values.service.port }}/api/graphql

Port-forward to try it locally:

  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "openshapeforge-api.fullname" . }} 3001:{{ .Values.service.port }}
  curl http://127.0.0.1:3001/api/health

{{- if .Values.workers.enabled }}

The {{ .Values.workers.role }} role runs as a separate Deployment
({{ include "openshapeforge-api.workerFullname" . }}, {{ .Values.workers.replicaCount }} replica(s)). It serves no
traffic, so it has no Service, no Ingress and no probes — its log is the only
signal that it is draining the queue:

  kubectl logs -n {{ .Release.Namespace }} deploy/{{ include "openshapeforge-api.workerFullname" . }}
{{- end }}

{{- if eq (default "" .Values.auth.bearer.audience) "" }}

WARNING: auth.bearer.audience is empty. With NODE_ENV=production the API will
refuse to start until a bearer audience and a strong internal context secret
are configured. Set auth.bearer.{jwksUri,issuer,audience} and provide
OPENSHAPEFORGE_INTERNAL_CONTEXT_SECRET (via database.existingSecret or
auth.internalContextSecret).
{{- end }}

{{- if and .Values.ingress.enabled .Values.ingress.allowPlaintext (not .Values.ingress.tls) }}

WARNING: ingress.allowPlaintext=true and ingress.tls is empty, so this Ingress
serves the API over HTTP. Bearer tokens and signed internal-context headers are
readable, and replayable, by anyone on the network path. This is only safe if
something upstream (load balancer, service mesh) terminates TLS and refuses
plaintext. Otherwise set ingress.tls.
{{- end }}

{{- if .Values.database.existingSecret }}

NOTE: credentials come from the existing Secret {{ .Values.database.existingSecret }}.
The chart cannot hash contents it does not render, so rotating a value in that
Secret will NOT roll the pods — they keep the credential injected at their last
start. After rotating, restart them explicitly:

  kubectl rollout restart -n {{ .Release.Namespace }} deploy/{{ include "openshapeforge-api.fullname" . }}
{{- if .Values.workers.enabled }}
  kubectl rollout restart -n {{ .Release.Namespace }} deploy/{{ include "openshapeforge-api.workerFullname" . }}
{{- end }}

(With chart-managed credentials a checksum/secret pod annotation does this for
you on every `helm upgrade`.)
{{- end }}
